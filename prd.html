1一、术语表

术语说明
微信扫码登录用户使用微信扫描PC端二维码完成登录（PC端专用）
微信一键登录用户点击微信登录按钮，跳转微信授权页完成登录（移动端H5专用）
小程序微信授权登录小程序内通过wx.login()获取code，服务端换取openid/unionid完成登录
openid微信用户在单个AppID下的唯一标识，不同端（PC网站应用、小程序）openid不同
unionid微信用户在同一微信开放平台账号下所有AppID的统一唯一标识，用于多端用户身份打通
platform登录来源标识：pc_web（PC端网站）、miniapp（小程序）
微信开放平台用于PC端网站应用接入微信扫码登录（open.weixin.qq.com）
微信公众平台用于小程序配置wx.login授权（mp.weixin.qq.com）
首次登录用户使用微信登录时，系统内无对应账号，需绑定手机号完成注册

2二、功能概述

核心目标

为数智聚模用户（PC端 + 小程序端）提供便捷的微信登录方式，降低登录门槛，提升用户转化率。两端通过unionid打通用户身份，同一微信号在不同端登录均映射到同一系统账号。

支持的登录方式

登录方式适用端优先级说明
微信扫码登录PC端Must展示二维码，用户手机扫码授权
微信一键登录移动端H5Should点击按钮跳转微信授权页
小程序微信授权登录微信小程序Mustwx.login()获取code，服务端换openid/unionid
账号密码登录PC端 + 小程序端Must传统登录方式
短信验证码登录PC端 + 小程序端Must手机号+验证码登录

5五、小程序端微信授权登录

⚠️ 说明

小程序端使用wx.login()获取code，与PC端扫码登录机制完全不同，需单独实现。但两端通过unionid打通用户身份（前提：小程序与网站应用均绑定到同一微信开放平台主体账号下）。

🚨 开发提醒

小程序端微信授权登录时，服务端必须同时获取并存储 openid + unionid。只存openid无法实现多端打通（openid在不同端不同，unionid才一致）。详见第7章。

5.1 登录流程

用户进入小程序 → 调用 wx.login() 获取 code
         │
         ▼
前端将 code 发送到商城服务端（/api/auth/miniapp/login）
         │
         ▼
服务端调用微信接口：
GET https://api.weixin.qq.com/sns/jscode2session
参数：appid / secret / js_code / grant_type=authorization_code
         │
         ▼
获得：openid（小程序openid）+ session_key + unionid（需已关注公众号或开放平台绑定时才有）
         │
  存储 openid/unionid（见第七章）
         │
  查询 wechat_auth 表：该 unionid 是否已绑定账号？
         │
    ┌────┴────┐
    │         │
  已绑定     未绑定（首次登录）
    │         │
    ▼         ▼
  直接登录   跳转绑定手机号页（小程序端）
  签发Token  （见第六章）
    │         │
    └────┬────┘
         ▼
    进入小程序首页

5.2 小程序端获取用户手机号

💡 重要说明

微信小程序支持getPhoneNumber组件一键获取用户手机号（需用户主动授权），可替代手动输入手机号+验证码的绑定流程，提升体验。

方案说明推荐度
getPhoneNumber组件授权用户点击按钮授权，小程序直接获取手机号（需申请权限）✅ 推荐
手动输入手机号+验证码与PC端一致，无需额外权限备选方案
⚠️ 阻塞项

getPhoneNumber需向微信申请"手机号快速验证组件"权限（企业主体），需在小程序开发前确认是否已申请。若未申请，首次登录统一走手动输入手机号+验证码流程。

5.3 注意事项

注意点说明
session_key安全性session_key仅在服务端存储，不传给前端，用于解密微信返回的加密数据
openid不同小程序openid ≠ PC网站openid，同一用户在两端openid不同
unionid获取条件用户须关注了绑定的公众号，或小程序与网站应用绑定到同一开放平台账号，否则unionid为空（见第七章降级策略）
code一次性wx.login()返回的code有效期5分钟，且只可使用一次

  • 后续微信登录（PC端或小程序端）直接进入，无需再次绑定
  • 同一手机号不可重复绑定不同微信号

绑定手机号服务端逻辑：

  1. 验证手机号格式（11位）
  2. 验证短信验证码有效性（6位，5分钟内有效）
  3. 查询该手机号是否已有账号：
    • 有 → 将 openid/unionid 关联到已有账号
    • 无 → 新建账号，再关联 openid/unionid
  4. 写入wechat_auth表（见第九章数据表）
  5. 删除/失效临时token，签发正式 JWT Token

7七、openid与unionid存储机制

7.1 存储时机

触发事件存储动作
微信授权回调（首次）写入新记录：openid、unionid、platform、user_id（绑定后写入）
再次登录（已绑定）查询wechat_auth表，校验 unionid/openid 是否存在
绑定手机号完成更新wechat_auth记录中的user_id字段

7.2 多端openid说明

端platform标识openid来源是否相同
PC端（网站应用）pc_web微信开放平台网站应用AppID与小程序openid不同
小程序端miniapp微信小程序AppID与PC端openid不同

同一用户在PC端和小程序端的openid不同，但unionid相同（需绑定到同一微信开放平台账号下）。

7.3 unionid获取失败的降级策略

⚠️ 关键说明

unionid不一定每次都能获取到。以下场景会导致unionid为空：

  • 小程序未绑定到微信开放平台账号
  • 用户未关注关联公众号（部分情况）
场景处理策略
unionid为空，openid存在以openid作为该端的唯一标识存储；多端打通功能暂时降级（等用户在另一端登录后补全unionid）
unionid和openid均为空视为授权失败，返回错误，引导用户重新登录
unionid已存在，本次带新端openid新增一条wechat_auth记录（platform不同），关联到同一user_id

字段为什么第一期就要建

unionid（可为空）先上线的端（如小程序）存好unionid，后上线端（如PC端）通过unionid自动打通
user_id（绑定后写入）两端共用同一user_id，打通的核心

8.3 打通逻辑示意（分阶段开发场景，两端谁先上都行）

💡 核心原则

谁先上线都可以，打通逻辑完全对称。关键是先上线端的 unionid 必须存好，后上线端通过 unionid 自动匹配。

场景A：小程序先上线 → PC端后上线

【阶段1：小程序先上线】
用户在小程序微信登录（首次）：
  → 服务端存入 wechat_auth：
    openid=xxx_miniapp, unionid=U001, platform=miniapp, user_id=（绑定后写入）
  → 用户绑定手机号 → user_id=10086

【阶段2：PC端后上线，同一用户PC端首次微信扫码登录】
服务端收到回调：
  → 获取到 openid=yyy_pc, unionid=U001（同一人，unionid相同）
  → 查询 wechat_auth 表：unionid=U001 已存在，对应 user_id=10086
  → 新增一条记录（platform=pc_web），关联到 user_id=10086
  → 直接签发 JWT Token，用户无感知登录成功，无需再次绑定手机号

场景B：PC端先上线 → 小程序后上线

【阶段1：PC端先上线】
用户在PC端微信扫码登录（首次）：
  → 服务端存入 wechat_auth：
    openid=xxx_pc, unionid=U001, platform=pc_web, user_id=（绑定后写入）
  → 用户绑定手机号 → user_id=10086

【阶段2：小程序后上线，同一用户小程序首次微信授权登录】
服务端收到 wx.login 回调：
  → 获取到 openid=yyy_miniapp, unionid=U001（同一人，unionid相同）
  → 查询 wechat_auth 表：unionid=U001 已存在，对应 user_id=10086
  → 新增一条记录（platform=miniapp），关联到 user_id=10086
  → 直接签发 JWT Token，用户无感知登录成功，无需再次绑定手机号
💡 总结

无论谁先上线，后上线端首次登录时的自动打通逻辑完全一致：查 unionid → 找到 user_id → 关联新记录 → 签发 Token。

9.1 接入流程

端接入方式申请入口说明
PC端微信开放平台 - 网站应用open.weixin.qq.com需企业资质+审核，获取PC专用AppID

🚨 开发提醒
  • 如果PC端网站应用和小程序没有绑定到同一微信开放平台主体账号，则两端获取的unionid不一致（或为空），多端账号无法打通。
  • 确认方法：登录微信开放平台 → 管理中心 → 确认"网站应用"和"小程序"均在同一账号下。
  • 无论哪端先上线，登录授权时必须同时获取并存储 openid + unionid，缺一不可。

9.2 PC端核心接口

获取授权码（扫码登录）：

GET https://open.weixin.qq.com/connect/qrconnect
参数：
  - appid: PC端网站应用AppID
  - redirect_uri: 回调地址（需URL编码，如 https://mall.qitai.com/auth/wechat/callback）
  - response_type: code
  - scope: snsapi_login
  - state: 防CSRF攻击的随机字符串（UUID，服务端存储，回调验证）

获取 Access Token + openid + unionid：

GET https://api.weixin.qq.com/sns/oauth2/access_token
参数：
  - appid: PC端AppID
  - secret: AppSecret（仅服务端调用）
  - code: 授权码（一次性，5分钟有效）
  - grant_type: authorization_code
返回：access_token、openid、unionid、expires_in

获取用户信息（昵称/头像）：

GET https://api.weixin.qq.com/sns/userinfo
参数：
  - access_token: 访问令牌
  - openid: 用户openid
  - lang: zh_CN
返回：openid、nickname、headimgurl、unionid
⚠️ 阻塞风险

微信2023年版本起对第三方平台获取用户信息有限制，部分场景需用户主动授权才可获取昵称/头像。若无法获取，系统可以不存储昵称/头像，登录功能不受影响。需在接入测试阶段验证是否能正常获取。

9.3 小程序端核心接口

获取openid/unionid（wx.login）：

服务端调用：
GET https://api.weixin.qq.com/sns/jscode2session
参数：
  - appid: 小程序AppID
  - secret: 小程序AppSecret（仅服务端调用）
  - js_code: wx.login()返回的code
  - grant_type: authorization_code
返回：openid、session_key、unionid（如能获取）

⚠️ 注意：session_key不传给前端，仅服务端存储，用于解密用户敏感数据。

15.4.1 用户表认证相关字段

字段类型说明
auth_statusvarchar(20)认证状态：none（未认证）/ personal（个人已认证）/ enterprise（企业已认证）
auth_timedatetime最近一次认证通过时间
personal_auth_idbigint关联个人认证记录ID（e签宝返回）
enterprise_auth_idbigint关联企业认证记录ID（e签宝返回）
⚠️ 开发提醒
  • auth_status 字段为登录后认证引导弹窗和下单拦截的核心判断依据，必须在建表时到位
  • 认证状态变更（e签宝回调确认认证通过）→ 服务端更新 auth_status + auth_time
  • 个人认证升级企业认证：auth_status 从 personal 变为 enterprise，原个人认证记录保留
